# Перенос моста CASCADE на сервер аналитики — скрипты (26.11.2026)

Скрипты написаны для Ubuntu 22.04 и запускаются на сервере аналитики под root. Адресов и секретов в них нет. Порядок, причины и откат — в `docs/stream/CHANGES/2026-11-26-avaria-mosta.md`, план — `docs/superpowers/plans/2026-11-26-most-na-servere-analitiki.md`, подробности с адресами — `backup-servers/PODROBNO-2026-11-26.md`.

## Порядок запуска (как было сделано)
1. `bridge_bundle.sh` — на СТАРОМ мосту: собирает `/root/ph2-bundle.tgz` (config.json, panel_secret, nginx.conf, caddy conf, unit панели, данные Caddy, `nat.rules` из текущих правил моста). Забрать на мак, залить на сервер аналитики, распаковать в `/root/cascade-ph2/bundle` (`tar -xzf … --strip-components=1`).
2. Положить на сервер в `/root/cascade-ph2/`: `guard.sh`, `a_packages.sh`, `b_code.sh`, `c_net.sh`, `d_web.sh`, `e_prep.sh`, `rollback.sh`.
3. `c_net.sh` — сеть: модули, sysctl, служба `cascade-nat` (nat.rules из bundle), проверка «остановить/запустить».
4. Проверка потока ≥100 КБ через новый адрес (клиент Xray на другом сервере; скрипты — `backup-servers/skripty/`).
5. `a_packages.sh` — nginx, libnginx-mod-stream, qrencode, python3-venv, git, curl, Caddy; демоны не запускаются (`policy-rc.d`), `caddy` и `nginx` отключены.
6. `b_code.sh` — `git clone` кода в `/opt/cascade`, коммит 69ae045, окружение Python.
7. `d_web.sh` — конфиг и panel_secret, nginx и Caddy (проверка настроек), панель на 127.0.0.1:8088, проверка подписки; Caddy и nginx остаются остановленными.
8. `e_prep.sh` — перед переключением домена: свежая копия конфига и данных Caddy (повторить п. 1 и распаковку), запуск Caddy и nginx, проверка изнутри, удаление копии секретов.
9. `rollback.sh` — полный откат (службы, правила, sysctl, каталоги, пакеты по `pkgs-added.txt`).

## Особенности (не повторять ошибок)
- НЕ запускать штатный `apply_rule` каскада на сервере с fail2ban: он собирает nfqws и вызывает `netfilter-persistent save`, который сохраняет все таблицы, включая цепочки fail2ban.
- `guard.sh` не даёт запускаться в окнах заданий аналитики (:19–:20, :39–:40, :44–:45; ночью 00:50–06:25 с интервалами).
- Caddy поднимать только когда домен указывает на этот сервер или сертификат далеко от окна продления; иначе он начнёт безуспешно продлевать копию.
- Бинарники из интернета на сервер аналитики не скачивать: команды отклоняются. Для тестов потока бинарь Xray брать с EST.
- Передача больших файлов с мака на сервер аналитики очень медленная (~20 КБ/с); нужное носить по сети между серверами, а не через мак.
